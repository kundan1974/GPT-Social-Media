# RoohKeSur Studio

Create complete, reviewable poetry productions in the GPT-Social-Media cloud environment. The creator supplies the poem, final Suno song or recitation recording. Use cloud-connected resources and verified cloud rendering; no local Mac or desktop Adobe dependency.

## Select the workflow

- A new poem or reel request without a finished song: read [Suno and paired videos](references/suno-and-paired-videos.md), return the complete Suno package, then wait for the creator's final song.
- A supplied finished song: use that same reference to create both video versions. Do not generate or substitute a new soundtrack.
- A poetry image/poster request: read [Poetry artwork](references/poetry-artwork.md).
- A creator recording: read [Recitation production](references/recitation-production.md).
- Before an external production operation or delivery: read the relevant sections of [Cloud tools and delivery](references/cloud-tools-and-delivery.md). Load other references only when they apply.

## Established defaults

Brand: RoohKeSur. Write accessible Hindi with familiar Urdu. Retain the poem's own language and script. Do not turn expressive Urdu into generic motivational prose.

Treat the supplied poem as source authority. Keep the original text and source version in private storage. Add musical tags and separate direction without silently rewriting, reordering, translating or inventing lines. Identify any proposed refrain repetition or adaptation separately.

A reel request normally requires:

| Output | Working default |
| --- | --- |
| Instagram / social | Portrait 9:16, 1080 x 1920, 30 seconds |
| YouTube | Landscape 16:9, 1920 x 1080, approximately 2-4 minutes |

Measure supplied audio; let actual performance and song sections govern timing. Resolve an audio/source duration outside the requested band before trimming meaningful verse, repeating it or stretching playback. Continue independent preparation while a needed answer is pending. Recompose each aspect ratio.

Artwork normally uses 4-6 exact lines, selected for a coherent thought unless already chosen. For recitation, preserve the creator's recording and human voice; a generated host or synthetic missing line is not an automatic replacement.

## Produce and review

1. Capture only missing inputs that materially affect the work: source, requested mode, final audio/recording, output goal and any spending ceiling. Reuse established decisions and permissions.
2. Identify the audience moment, emotional movement, central metaphor and satisfying ending. Choose tools and production scope that serve the poem.
3. Discover the current tools in this cloud host, their input requirements, configured cost and usable output route. Verify relevant access before relying on it.
4. Keep accepted references, clean footage, original audio, editable Unicode text, timings and a rebuild route. Copy-only changes should not regenerate visuals.
5. Inspect actual images, full rendered videos and complete audio. Correct language, motion, continuity, framing, captions, sound and endings before reporting ready.
6. Save durable private cloud outputs; return previews and accessible deliverable links with the full package. Distinguish generated, saved, reviewed, ready-for-review, approved and published.

For each video package deliver the requested versions, cover(s), caption.txt, MUSIC.md and UPLOAD-PACKAGE.md. MUSIC.md identifies the supplied selected song or other authorised audio, source/version, passage, mood and verified rights status. It does not certify rights from a recommendation. Include supported editable/rebuild materials and caption files where useful.

Use [the private job-manifest template](assets/templates/job-manifest.json) to retain source/audio versions, job IDs, configured costs, selected passage, output identities, QA and status. This public template contains no real production input; instantiated manifests belong in private storage.

## Completion and authority

Progress autonomously through routine reversible preparation and editing within the request and agreed budget. Ask at a concrete unresolved boundary, such as a poem adaptation, new spend beyond the ceiling or a missing required input; do not ask for approval at every step.

When the review package is verified and accessible, return **Ready for your review** with every required output. Use the cloud host's configured completion notification where supported; do not claim push/email delivery without an actual configured channel and event. A paused chat is not a background worker. Persist job IDs and use a supported continuation/monitor when needed.

Await the creator's review before publication. Report a failure or required input promptly, without repeated unchanged-status alerts. Never describe a prompt package, queued job or cloud preview as a completed saved video.

## Evolve the workflow

Apply specific user corrections to the relevant reference or template. Keep the entrypoint concise and conditional. With actual results, compare similar formats, lengths and observation ages; learn from retention, shares, saves and meaningful response. Do not invent metrics, guarantee virality or hard-code posting-time/hashtag formulas.
