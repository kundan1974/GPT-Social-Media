# GPT-Social-Media working instructions

This repository backs the GPT-Social-Media cloud environment.

- Run production and rendering in cloud services or the selected cloud host. Do not use the creator's Mac or desktop Adobe applications.
- Use [.agents/skills/roohkesur-studio/SKILL.md](.agents/skills/roohkesur-studio/SKILL.md) for requested Hindi/Urdu poetry songs, reels, artwork and recitation edits.
- Keep the supplied poem authoritative. Surface proposed adaptations separately.
- A reel request normally means a 30-second vertical social version plus a horizontal YouTube version of approximately 2-4 minutes, governed by supplied audio.
- Keep unpublished poems, voices, footage, personal reference photos, credentials and private asset URLs out of this public repository. Use durable private cloud storage for media and private production records.
- Persistent creator preference: use a single private DigitalOcean Spaces workspace at `RoohKeSur/projects/`, with one dated, descriptive subfolder per project. Each project has `inputs/`, `working/`, `generated/`, `deliverables/`, `manifests/` and `rebuild/` subfolders. Preserve untouched creator uploads in `inputs/`; store drafts and previews in `working/`, generated media in `generated/`, review/final exports in `deliverables/`, private production records in `manifests/`, and editable/rebuild materials in `rebuild/`. Read the private `RoohKeSur/WORKSPACE.md` for project locations; keep specific project identities and asset keys out of Git. Reuse this convention for future projects unless the creator changes it.
- Preserve the user's review gate: complete and verify a review package, report ready, then await their review before publication.
- Report exposed tools, verified connections, completed operations and publication as distinct states.
